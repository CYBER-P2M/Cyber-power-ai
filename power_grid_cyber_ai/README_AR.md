# Report Guard v2 - تثبيت التصحيح

هذه حزمة تصحيح للإضافة الموجودة، وليست مشروعًا كاملًا.
انسخ مجلد tools إلى جذر مشروعك. لا تضع ملفاته في dashboard/pages.

أوقف Streamlit ثم نفذ:

python tools/install_report_guard_v2.py --check
python tools/install_report_guard_v2.py --apply
python tools/test_report_guard_v2.py --installed
python -m streamlit run dashboard/app.py

المثبت يأخذ نسخة احتياطية من src/llm_report.py ثم يضيف طبقة حماية في نهايته.
لا يغير التدريب أو نموذج التصنيف أو risk_score أو ملفات baseline.

كل أقسام السرد النهائي تبنى بقوالب من packet. يستدعى Qwen كما في السابق،
لكن نصه مجرد مسودة لا يعتمد عليها في التقرير النهائي. هذا إجراء محافظ متعمد،
وليس ادعاء بوجود مدقق دلالي كامل. قد يبقى رأس التقرير يقول LLM + automatic verification؛
ملاحظة guard-v2 في التقرير توضح أن النص النهائي مبني بالقوالب.

يتغير اسم المؤشر في نص التقرير إلى Non-Normal Score فقط؛ مؤشر الواجهة القديم لا يتغير.
الأرقام التاريخية تُعرض من الحزمة، ولا تضمن صحة تقييم النموذج أو فصل بيانات الاختبار.
يبقى baseline القديم وحدوده كما هو؛ هذه الحزمة لا تصلح طريقة حساب z أو دائرية الزوايا.

لإزالة تقرير قديم من session_state أغلق تبويب التطبيق وافتح جلسة جديدة بعد إعادة التشغيل،
ثم ارفع CSV واختر Attack/Fault واضغط إنشاء التقرير. الملفات القديمة لا يعاد تحريرها تلقائيًا.

الاختبار المحلي: 12/12 مع packet اصطناعي ومدقق v1 محاكى، دون Qwen أو نماذجك الحقيقية.
اختبار --installed يستدعي مدققك الموجود مع packet اصطناعي، وليس صف CSV حقيقيًا.
اختبار tools/test_report.py القديم قد يفشل في فحص no auto-corrections بسبب ملاحظة guard-v2
الإضافية دائمًا؛ لا تعتبر ذلك وحده دليلاً على فشل التصحيح.

للتراجع: أوقف التطبيق وأعد نسخة llm_report.py.before_guard_v2_*.bak إلى src/llm_report.py.
